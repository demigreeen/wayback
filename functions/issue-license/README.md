# issue-license — оплата и выдача ключа

Облачная функция. Делает две вещи, и обе требуют секретного ключа ЮKassa,
которому место только на сервере:

1. **Создаёт платёж.** Магазин подключён по протоколу API — статичной ссылки
   на оплату там не бывает. Сайт присылает почту покупателя, функция создаёт
   платёж на свою сумму и возвращает адрес страницы оплаты.
2. **Выдаёт ключ.** Получив от ЮKassa уведомление об успехе, перепроверяет
   платёж через API, подписывает его номер и отправляет письмо со ссылкой.

Логика и формат подписи проверены на совпадение с `site/js/license.js` —
подпись отсюда браузер примет так же, как принял бы подпись, выданную
`keygen.html` вручную.

Названия пунктов меню в консоли Yandex Cloud могли измениться с момента
написания — общий порядок шагов от этого не меняется.

---

## Что понадобится завести самому

Это единственная часть проекта, требующая внешних аккаунтов — сам сайт
их не требует. Создать аккаунты должны вы: это действие с деньгами
и доступом, его нельзя делать за вас.

1. **Аккаунт в Yandex Cloud** — cloud.yandex.ru, вход через Яндекс ID.
   Бесплатный тариф покрывает миллион вызовов функции в месяц — для
   объёма продаж этого сайта расходов не будет, но для создания функции
   Yandex Cloud обычно просит привязать карту.
2. **ЮKassa для самозанятых** — вы уже начали подключение. Понадобится
   секретный ключ из **Настройки → API ключи** (не тот, что вставляется
   в код сайта, — тот публичный, а этот, наоборот, никому не показывается)
   и включённые **HTTP-уведомления** в **Настройки → Уведомления**.
3. **Почтовый ящик для отправки писем**, лучше отдельный от личного —
   например, `noreply@wayback.pro` или обычный ящик на Яндексе. Подойдёт
   способ, которым вы уже пользуетесь для почты на домене; если его нет —
   быстрее всего завести бесплатный ящик на Яндексе и создать для него
   пароль приложения (Управление аккаунтом → Пароли и авторизация →
   Пароль приложения — обычный пароль для входа не подойдёт, SMTP
   требует именно пароль приложения).

## Шаг 1. Собрать архив

```bash
python tools/build_function.py
```

Скрипт поставит зависимости, соберёт `build/issue-license.zip` и проверит
его. Руками архив лучше не делать: в нём легко ошибиться дважды.

Во-первых, архивировать нужно содержимое папки, а не саму папку — иначе
Yandex Cloud не найдёт `index.js`. Во-вторых, `Compress-Archive` в Windows
PowerShell пишет пути через обратный слэш, а формат ZIP требует прямой:
на Linux такой архив разворачивается в плоский набор файлов с именами
вроде `node_modules\nodemailer\index.js`, и функция падает на `require`
так, будто зависимостей нет вовсе. Скрипт проверяет и то, и другое.

## Шаг 2. Создать функцию

В консоли Yandex Cloud: **Cloud Functions → Создать функцию**.

- Среда выполнения: **Node.js 18** (или новее, если 18 не предложат)
- Точка входа: `index.handler`
- Загрузить архив из шага 1
- Таймаут — 10 секунд достаточно с запасом

## Шаг 3. Переменные окружения

В настройках функции, вкладка **Переменные окружения**:

| Имя | Значение |
|---|---|
| `PRIVATE_KEY_JWK` | содержимое файла `wayback-private-key.json` целиком, одной строкой JSON |
| `YOOKASSA_SHOP_ID` | ID магазина из личного кабинета ЮKassa |
| `YOOKASSA_SECRET_KEY` | секретный ключ ЮKassa — именно секретный, не публичный |
| `AMOUNT` | `199` — цена в рублях. На неё создаётся платёж, она же проверяется при выдаче: оплата меньшей суммы ключ не открывает |
| `SITE_URL` | `https://wayback.pro` |
| `SMTP` | строка подключения к почте — см. ниже. Либо вместо неё четыре отдельные переменные `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` |
| `MAIL_FROM` | адрес отправителя |
| `OWNER_EMAIL` | ваша личная почта — сюда падает копия каждого письма |

Почту можно задать одной строкой, если заводить четыре переменные неудобно:

```
smtps://имя%40ящик.ру:парольприложения@smtp.yandex.ru:465
```

Символ `@` внутри имени пользователя записывается как **`%40`** — иначе
разбор адреса споткнётся о второй `@`. Пароль здесь — пароль приложения,
обычный пароль от почты SMTP не примет.

Примеры готовых строк:

```
Яндекс:  smtps://noreply%40wayback.pro:пароль@smtp.yandex.ru:465
Gmail:   smtps://имя%40gmail.com:пароль@smtp.gmail.com:465
```

`PRIVATE_KEY_JWK` — самое чувствительное значение здесь: у кого он есть,
тот может выпускать бесплатные покупки. Это единственное место, где
закрытый ключ покидает ваш компьютер, — храните к нему доступ так же
бережно, как к самому файлу.

## Шаг 4. Сделать функцию доступной по HTTP

**Функция → вкладка Триггеры → Добавить триггер → тип HTTP.** Проще
всего сделать вызов публичным без API Gateway: у функции есть встроенный
адрес вида `https://functions.yandexcloud.net/<id-функции>`; чтобы его
понимал внешний вызывающий (ЮKassa), функции нужно назначить роль
`serverless.functions.invoker` для `allUsers` — это делается в настройках
функции, вкладка **Права доступа**.

## Шаг 5. Подключить в ЮKassa

Личный кабинет ЮKassa → **Интеграция → HTTP-уведомления** (именно
«Интеграция», а не «Настройки»): вставить адрес функции из шага 4
и отметить событие **`payment.succeeded`**.

Требования ЮKassa к адресу — протокол HTTPS и порт 443 или 8443.
Адрес функции Yandex Cloud им соответствует.

Подлинность уведомлений функция проверяет сама и самым надёжным способом:
берёт из уведомления только идентификатор платежа и перезапрашивает его
статус у ЮKassa своим секретным ключом. Подделанное уведомление такой
проверки не проходит, поэтому сверять IP-адреса отправителя не нужно.

## Шаг 6. Вписать адрес функции в сайт

В `site/js/license.js` в `PAY_API` поставить тот же адрес функции.
Без него сайт покажет вместо кнопки почту для ручной выдачи.

## Шаг 7. Проверить

Откройте плеер, нажмите «Убрать водяной знак», введите свою почту
и оплатите. Письмо должно прийти на указанную почту, копия —
на `OWNER_EMAIL`.

Если ЮKassa откажет на создании платежа, в логах функции будет её ответ
целиком. Самая вероятная причина — блок `receipt`: он нужен для чека,
но у части магазинов чек формируется иначе, и тогда блок надо убрать
из `createPayment` в `index.js`.

Если письмо не пришло — в консоли Yandex Cloud у функции есть вкладка
**Логи**: там видно, на каком шаге функция остановилась (текст ошибки
пишется через `console.error`).

## Обновление функции после правок кода

Тот же скрипт и та же загрузка: **Редактор → источник кода ZIP-архив →
загрузить → Сохранить изменения**. Переменные окружения при этом
сохраняются, заново вводить их не нужно.

## Как отключить конкретную покупку

Если ссылка окажется в открытом доступе: возьмите ID платежа из письма
на `OWNER_EMAIL` (или из истории платежей ЮKassa) и впишите его строкой
в `REVOKED` в `site/js/license.js`, затем отправьте сайт. Действует
со следующей загрузки страницы у любого, кто откроет её заново.
